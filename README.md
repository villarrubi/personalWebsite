# Alejandro Villarrubia · Personal website

Portfolio bilingüe inglés/español centrado en ingeniería de software, IA local y sistemas físicos, sobre una paleta azul noche. La portada presenta el nombre a gran escala, una introducción y los accesos a proyectos y contacto. El experimento de paisaje interactivo está retirado temporalmente. Los proyectos publicados se recorren en una única escena orbital, con todos los proyectos en un único catálogo sin filtros, una vista previa del proyecto seleccionado, fichas y páginas de detalle y CV en ambos idiomas. La entrada presenta un circuito luminoso cuyas partículas se reúnen para formar el nombre y la frase directamente en la portada.

## Abrir en Windows

Doble clic en **Abrir web.cmd**. La vista previa abre la portada. La entrada se reproduce al abrir, refrescar o volver a la portada cuando el nombre está en pantalla. Las visitas a una sección inferior conservan su posición y abren directamente el contenido. `?intro=off` y `?motion=off` permiten omitirla. La entrada de circuito se mantiene completa con cualquier preferencia del sistema; si Canvas no está disponible se usa un fundido breve. Requiere Node.js 22 o posterior. No instala dependencias.

```powershell
npm run dev
```

Vista local: http://127.0.0.1:4173/en/ . El idioma predeterminado es inglés, con español disponible desde el selector ES. La carpeta `dist/` se puede servir en cualquier alojamiento estático. Publicación en GitHub Pages: https://villarrubi.github.io/personalWebsite/ . El workflow `.github/workflows/pages.yml` construye y valida la web antes de publicar cada cambio de `main`. `SITE_BASE_PATH` adapta los enlaces, estilos y recursos a la subcarpeta de Pages; sin esa variable la vista local sigue usando la raíz. Cada build añade una versión basada en el contenido a los scripts, estilos y sus importaciones, para que el navegador cargue los cambios publicados sin reutilizar JavaScript antiguo de la caché.

## Gestor de proyectos

Acceso: `/admin/` (en GitHub Pages, https://villarrubi.github.io/personalWebsite/admin/). La página tiene `noindex` y no incluye contraseñas ni permisos: se entra con un **token de acceso de GitHub** de grano fino, que sólo se envía a la API de GitHub y se guarda en la pestaña (o en el dispositivo si se marca «Recordar»).

Para crear el token: GitHub → Settings → Developer settings → Fine-grained tokens → *Generate new token*; *Repository access*: sólo `personalWebsite`; *Permissions*: **Contents: Read and write** (y, opcional, **Actions: Read-only** para ver en el panel cuándo termina la publicación). El panel incluye estas instrucciones y un enlace directo.

El panel lista todos los proyectos con búsqueda y filtros (publicados y borradores) y permite crear, editar y eliminar fichas: nombre, identificador, año, orden, publicación, destacado, estado, visibilidad, repositorio, demo, tecnologías, ilustración, todos los textos en español e inglés, imágenes (las grandes se reducen y convierten a WebP en el navegador) y caso de estudio. Antes de guardar aplica la misma validación que el build, por lo que una ficha incompleta no puede publicarse. Cada acción es un único commit en `main` (ficha e imágenes juntas); si la ficha cambió en GitHub después de abrirla, el panel lo avisa en lugar de sobrescribirla. Al eliminar, se pide escribir el identificador y se pueden borrar también las imágenes que ningún otro proyecto usa.

Pages CMS sigue configurado en `.pages.yml` como alternativa.

Cada guardado crea un cambio en `main` y activa la publicación existente. La web se actualiza cuando terminan las comprobaciones y el despliegue. Si un campo obligatorio para publicar está incompleto o una imagen referenciada no existe, el despliegue falla y permanece la última versión válida. Se puede consultar el resultado desde «Consultar la última publicación». El historial de Git permite recuperar contenido eliminado.

Los proyectos nuevos empiezan como borradores. Para publicar, completa en ambos idiomas el área, resumen, idea, lista de funcionalidades y estado actual; añade el año y, si el código es público, su repositorio. El identificador debe coincidir con el archivo y mantenerse estable al editar. Los textos son texto plano, no HTML. La imagen principal (`cover`) aparece en la ficha y la cabecera; `capture` es una imagen adicional. Cada imagen publicada necesita su descripción en español e inglés (`coverAlt` o `captureAlt`), editable desde el gestor. Describe qué muestra la captura y diferencia imágenes de pantallas distintas; el build rechaza imágenes publicadas sin estas descripciones. `caseStudy` permite editar el reto, la aportación y los componentes del sistema.

**Oculto no significa confidencial:** este repositorio es público. Un borrador no se incluye en las páginas generadas, pero su JSON y las imágenes siguen en GitHub y en el historial. No se deben guardar secretos o material privado en las fichas.

El dominio y el alojamiento son independientes del editor. En un dominio propio servido desde la raíz, construye sin `SITE_BASE_PATH`; en una subcarpeta, indica su prefijo. Los archivos conservan rutas `/assets/images/...` y el build adapta los enlaces. `dist/` se puede publicar en cualquier alojamiento estático. Si se abandona GitHub como proveedor de contenidos, los JSON e imágenes son portables; habría que sustituir la conexión del editor y el proceso de publicación.

## Publicar u ocultar proyectos

Cada ficha de `content/projects/` tiene controles independientes:

- `published: true`: aparece en la web. `false` o ausencia del campo: oculto. El filtro se aplica a las órbitas, los diálogos, las páginas de detalle y los enlaces entre proyectos.
- `status`: estado editorial del proyecto (`built` o `development`). No determina si se publica ni su prioridad; se mantiene manualmente según indique el autor.
- `visibility`: visibilidad del **código fuente** (`public` o `private`). Un proyecto privado puede tener una ficha pública, y un repositorio público puede quedarse fuera del portfolio.
- `featured` define destacados/complementarios; `order` define el orden dentro de cada grupo. No se eligen proyectos automáticamente por su estado ni por actividad de GitHub.
- `demo`: enlace opcional a una aplicación que el autor haya decidido mostrar.

Tras editar archivos localmente, ejecutar `npm run build` y `npm run check`. Desde el gestor, esas comprobaciones se ejecutan en GitHub antes de publicar. El build regenera `dist/` y elimina las páginas antiguas de proyectos ocultados o borrados.

LiDAR y Desarrollo Web II quedan con `published: false`. Los demás conservan su estado, grupo y orden anteriores, sin reclasificarlos. Ocultar una ficha del sitio no elimina el contenido del repositorio ni su historial, y tampoco modifica el CV o la trayectoria profesional. La biografía deja de enlazar a una ficha si se despublica. La portada no enlaza directamente a ninguna ficha seleccionada de forma implícita.

## Experimento de portada

El paisaje interactivo se ha retirado temporalmente de ambos idiomas, incluidos el rótulo, los controles y su carga de JavaScript. La portada compacta centra el nombre y sus enlaces, y acerca el comienzo de los proyectos a la primera pantalla. El nombre ocupa una línea en escritorio y dos en móvil. Conserva los enlaces a proyectos, contacto y la entrada de circuito, junto con el fundido del fondo hacia la sección siguiente.

Se conservan el generador, el SVG de respaldo y sus comprobaciones por si se recupera más adelante. La entrada de circuito se adapta al idioma y al tamaño de pantalla sin capturar la portada.

## Entrada de circuito

La secuencia dura 4,8 segundos: pulsos cian y ámbar recorren 48 pistas principales y 96 ramificaciones con destinos repartidos por las letras, sin chip ni punto de convergencia central. Las pistas tienen codos suavizados, componentes pequeños y nodos con ondas de activación. Dos trenes de luz por pista, estelas, partículas de fondo y marcas de registro alrededor del texto aportan detalle y profundidad; los brillos usan sprites pequeños reutilizados para evitar filtros costosos por fotograma. Las partículas forman el nombre y la frase en las posiciones exactas de los textos reales de la portada, incluido el punto del apellido. Se muestrean los grafemas del DOM con sus fuentes, colores, espaciado, cursivas y saltos de línea actuales. Al solidificarse, se revelan esos mismos elementos HTML; permanecen en su sitio mientras aparecen por etapas cabecera, fondo, descripción, enlaces y proyectos. No hay un segundo nombre superpuesto ni una firma que desaparece para repetir la portada.

El renderizado usa Canvas 2D, hasta 2.200 partículas y una resolución máxima de 1,5 píxeles por píxel CSS. La geometría se recalcula cuando cambian el tamaño, las fuentes o la posición del texto. No descarga modelos ni crea un contexto WebGL. Las visitas ancladas o restauradas por debajo de la portada conservan su desplazamiento y abren directamente el contenido, sin una animación fuera de pantalla. La cabecera y las órbitas se comprueban también después de una entrada completa, sin usar `?intro=off` en esa revisión.

Se reproduce en cada apertura, recarga y regreso desde el historial. `?intro=off` y `?motion=off` permiten omitirla. El botón de salto y Escape restauran inmediatamente la navegación, el desplazamiento y el foco. Mientras está abierta, el contenido subyacente permanece inerte. Se bloquean la rueda, el desplazamiento táctil y las teclas de scroll hasta finalizar o saltar la intro, también durante el fundido final. El suavizado de scroll cancela cualquier movimiento pendiente y no programa desplazamientos durante la entrada; el zoom y la activación del botón de salto siguen disponibles. Al ocultar la pestaña se pausa el reloj y el límite de seguridad; al volver se reanuda sin saltos. La preferencia de movimiento del sistema no sustituye la entrada por un fundido ni oculta el control de la cabecera. Si Canvas no está disponible, se revelan los mismos textos y el resto de la portada con fundidos suaves en 1,65 segundos, sin pulsos ni partículas.

Si falla el arranque, la cortina se retira después de 12 segundos visibles; si deja de llegar un fotograma durante la secuencia, se libera la página tras 8 segundos visibles. Sin JavaScript se accede directamente al contenido. `npm run check` verifica también finalización, salto, Escape, foco, estado inerte, pestañas ocultas, historial, ambos idiomas y enlaces de exclusión.

## Accesibilidad y SEO

Los contadores de los grupos conservan la opacidad completa para mejorar su contraste. El nombre accesible del botón de animación coincide con su acción visible, también cuando en móvil solo se muestra el icono. Las capturas tienen descripciones específicas en los dos idiomas, y las ilustraciones decorativas permanecen ocultas a los lectores de pantalla.

`SITE_URL` configura la dirección pública completa, incluida la subcarpeta y preferiblemente la barra final. Por defecto es `https://villarrubi.github.io/personalWebsite/`. Es independiente de `SITE_BASE_PATH`, que adapta los enlaces de navegación y recursos: una vista local conserva las URL canónicas de producción. Al cambiar de dominio, configura ambas variables según el nuevo alojamiento.

El build genera `canonical`, `og:url`, alternativos `hreflang` absolutos y `sitemap.xml` para las páginas publicadas de ambos idiomas. La portada raíz apunta a `/en/` como canónica; administración y 404 llevan `noindex` y quedan fuera del sitemap. Se puede enviar la URL pública del sitemap a Search Console para facilitar su descubrimiento. Las comprobaciones automáticas validan estas salidas, las descripciones de imágenes y las preferencias de movimiento; no sustituyen una revisión manual con teclado y lector de pantalla.
